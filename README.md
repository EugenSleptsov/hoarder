# hoarder

bot keeping items

Бот на Go, который прогнозирует расход домашних вещей и сам выбирает день, когда уточнить остаток или напомнить о пополнении. Пользователь отвечает на вопросы, а не ведёт журнал каждого использования.

**Статус: первая запускаемая версия Telegram-бота с inline-кнопками, callback-обработчиками и SQLite.** Есть добавление предметов, сохраняемые диалоги, независимые планы проверок, ежедневное меню вопросов и список рекомендаций купить. Полный сценарий проверяется на поддельном Telegram API и настоящем SQLite. Живое подключение, серверное развёртывание и домашний пилот не проводились.

## Основные правила

- **Предметы независимы.** Ответ о пасте не меняет прогноз бумаги. Общие только час доставки и представление вопросов; нет общего лимита предметов на день.
- **Резерв — фиксированный допуск на ошибку.** `with_reserve` меняет границу пополнения; размер резерва и целевой запас не увеличиваются автоматически.
- **Прогноз — основной механизм.** Не нужно самостоятельно сообщать об открытии резерва или каждом использовании.
- **Неизвестно — не значит не использовали.** Пропущенный ответ не останавливает расход. Рекомендация купить не считается покупкой. «Уже купили» уточняет текущий остаток, не создавая выдуманную покупку в момент ответа.

## Кнопочный интерфейс

```text
/start → [Добавить предмет]
                 ↓
          Название текстом
                 ↓
      [С резервом] [Без резерва]
                 ↓
       Срок расхода упаковки
                 ↓
       Число закрытых упаковок
                 ↓
    [Полная] [75%] [50%] [25%] [Пусто]
```

Повторная проверка предлагает также «Не знаю / не смотрел» и «Не использовали» с подтверждением интервала. Иногда уточняется отсутствие пополнений для корректного обучения. Первой версии может требоваться несколько нажатий на предмет; снижение этой нагрузки ещё нужно проверить на практике.

Каждая кнопка вызывает настоящий `callback_query`. Обработчик проверяет владельца, сообщение, разрешённое действие, версию экрана и ревизию предмета. Двойное нажатие не применяет наблюдение повторно. Состояние диалога сохраняется после каждого шага, поэтому его можно продолжить после перезапуска. Уведомление о callback отправляется и при отказе; готовый ответ сохраняется до обновления сообщения в Telegram.

Команды: `/items` — реестр, `/today` — наступившие вопросы, `/shopping` — рекомендации пополнить, `/add` — добавление. У названия есть текстовый ввод, остальные основные шаги — кнопки.

## Запуск

Нужны Go и C-компилятор для SQLite/CGO. CI использует Go 1.27.1; `go 1.23.0` в модуле задаёт совместимость языка, а не рекомендованную production-версию.

```sh
git clone https://github.com/EugenSleptsov/hoarder.git
cd hoarder
make check
mkdir -p bin
CGO_ENABLED=1 go build -o bin/hoarder ./cmd/hoarder

# Подставьте свой положительный числовой ID личного чата.
export HOARDER_CHAT_ID='YOUR_NUMERIC_PRIVATE_CHAT_ID'
# Файл с токеном создаётся вне репозитория; не публикуйте его.
export TELEGRAM_BOT_TOKEN_FILE='/absolute/private/path/telegram-token'
export HOARDER_TIMEZONE='Europe/Berlin'
export HOARDER_POLL_TIME='21:00'
export HOARDER_DB='data/hoarder.db'

./bin/hoarder
```

После запуска отправьте `/start` боту из разрешённого личного чата. Процесс рассчитан на одного владельца и одну копию на базу/токен. По умолчанию допустимое опоздание ежедневной доставки — 30 минут в пределах той же локальной даты. В пустой день бот молчит. Обычные команды доступны в любое время.

[Подробный запуск, настройки, отказы и резервные копии](docs/running.md). Смена уже сохранённого часа/зоны пока требует отдельной миграции; нельзя просто поменять environment и незаметно сдвинуть старые планы.

## Компоненты

| Компонент | Реализация |
|---|---|
| `internal/item` | Независимое состояние, интервальные наблюдения, добавления, replay-safe события |
| `internal/forecast` | Базовый прогноз двух границ: пополнение и исчерпание |
| `internal/schedule` | Общий час, IANA-зона и переходы летнего/зимнего времени |
| `internal/app` | Планирование одного предмета и транзакционные контракты |
| `internal/dialog` | Версионированная машина состояний inline-кнопок |
| `internal/sqlstore` | SQLite, транзакции, журнал событий, optimistic revisions, replay и backup |
| `internal/bot` | Авторизация, команды, callback-диалоги, список покупок, ежедневные сессии и outbox |
| `internal/telegram` | HTTP Bot API, сообщения, редактирование, polling и подтверждения callback |
| `cmd/hoarder` | Запускаемый процесс, конфигурация, завершение по сигналу, `-backup` |
| `cmd/hoarder-sim` | Воспроизводимый офлайн-сценарий ядра без Telegram |

## Проверки

`make check` запускает форматирование, `go vet` и тесты с race detector. Интеграционные сценарии проверяют кнопочное добавление, ответы, перезапуск, устаревшие/повторные callback, независимость предметов, список покупок, пагинацию всех вопросов и границы ежедневной доставки. SQLite проверяется реальными временными базами, включая rollback, replay и восстановление backup.

[Зафиксированные результаты и границы проверки](docs/verification.md). Симуляция и тесты не доказывают точность бытового прогноза.

## Ограничения

`interval-baseline-v1` **не обучает сезонность** и не рассчитывает откалиброванные вероятности. При внезапном скачке расхода наличие не гарантируется. Интерфейс пока поддерживает до трёх закрытых и одну открытую стандартную упаковку. Начальные настройки: резерв 0/1 упаковка, время на покупку 3 дня, максимальный промежуток физической проверки 90 дней.

Пауза/удаление/изменение конфигурации предмета, несколько пользователей, health endpoint, автоматическая ротация backup и очистка старых служебных записей пока не реализованы. Внешнее первое сообщение может продублироваться при падении между принятием запроса Telegram и записью `message_id`; exactly-once доставка не заявляется.

Ни токены, ни рабочую базу, ни личный реестр не следует добавлять в Git. Автоматических заказов/платежей, медицинских гарантий наличия и учёта сроков годности нет.
