# hoarder

bot keeping items

Бот, который прогнозирует расход домашних вещей и сам выбирает день, когда стоит уточнить остаток или напомнить о пополнении. Пользователь отвечает на редкие вопросы, а не ведёт журнал расхода.

**Текущий статус: архитектура и исполняемый прототип ядра на Go. Это ещё не законченный Telegram-бот.** Прогноз, модель предмета, календарное расписание, HTTP-адаптер Telegram и офлайн-симуляция реализованы. База данных, обработчики диалогов, постоянные сессии опроса и запускаемый бот-демон пока только спроектированы.

## Основные правила

- **Предметы независимы.** Ответ о пасте не меняет прогноз бумаги. Общие только час доставки вопросов и их представление в одной сессии.
- **Резерв — фиксированный запас на ошибку.** Свойство `with_reserve` меняет границу пополнения, но алгоритм никогда не увеличивает резерв или целевой запас автоматически.
- **Прогноз — основной механизм.** Не требуется самостоятельно сообщать об открытии резервной упаковки или каждом использовании.
- **Неизвестно — не значит не использовали.** Пропущенный ответ не останавливает расход. Рекомендация купить не считается покупкой; подтверждённое добавление увеличивает текущий остаток, а не сбрасывает его до полного.

## Что находится в репозитории

| Компонент | Состояние |
|---|---|
| `internal/item` | Интервальные остатки, независимое состояние, наблюдения, добавления, защита от повторного применения событий |
| `internal/forecast` | Детерминированный базовый прогноз, две границы — пополнение и полное исчерпание; резерв неизменен |
| `internal/schedule` | Общий час в заданной временной зоне, календарные даты, переходы летнего/зимнего времени |
| `internal/app` | Планирование одного предмета и контракты будущего транзакционного хранилища; реализация хранилища отсутствует |
| `internal/telegram` | HTTP-клиент Bot API: сообщения, редактирование, кнопки, ответы на callback, polling; не готовые пользовательские диалоги |
| `cmd/hoarder-sim` | Воспроизводимая офлайн-симуляция, не подключающаяся к Telegram |
| `.github/workflows/ci.yml` | Форматирование, `go vet`, тесты с race detector, покрытие и запуск симуляции |

## Запуск прототипа

```sh
git clone https://github.com/EugenSleptsov/hoarder.git
cd hoarder

go test ./...
go run ./cmd/hoarder-sim

# Полная проверка, включая race detector:
make check
```

Симуляция выводит JSON: прогноз остатка, причину проверки, желательный срок и ближайший подходящий общий час опроса. В ней изменение пасты не сдвигает прогноз другого предмета. Данные синтетические; это проверка логики, а не доказательство точности модели в быту.

Для симуляции не нужны токен, база данных или внешние зависимости Go. Директива `go 1.23.0` задаёт минимальную языковую совместимость, а не рекомендуемую версию для эксплуатации. CI зафиксирован на Go 1.27.1. Для сетевого развёртывания следует использовать поддерживаемую версию с актуальными исправлениями безопасности.

**Команды запуска полного бота сейчас нет:** `cmd/hoarder` ещё не реализован. Добавление токена само по себе не включает автоматические опросы.

## Ограничения текущей модели

`interval-baseline-v1` использует диапазоны правдоподобного остатка и скорости, а не откалиброванные вероятности. Она **не обучает сезонность** и не гарантирует наличие при внезапном скачке расхода. Неизвестные покупки обновляют оценку текущего состояния, но не превращаются в выдуманные точные данные для обучения. Пустая упаковка не считается закончившейся ровно в момент ответа.

Следующий этап — SQLite с журналом событий и транзакционной обработкой, затем устойчивые ежедневные сессии и настоящие диалоги. Сезонность, нерегулярный спрос и сокращение числа вопросов проверяются после появления наблюдений и сравнения с простыми индивидуальными напоминаниями. Размер физического резерва при таком сравнении остаётся фиксированным.

## Данные и безопасность

Не добавляйте токены, содержимое домашнего реестра или рабочую базу в Git. Текущие тесты используют локальный HTTP-сервер и заведомо фиктивный токен. Будущий бот должен принимать команды только из явно разрешённого чата; правило «первый написавший становится владельцем» не используется.

Автоматические покупки и платежи, медицински критичные гарантии наличия и учёт сроков годности не входят в начальную версию.
