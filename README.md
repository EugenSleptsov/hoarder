# hoarder

bot keeping items

Бот на Go, который прогнозирует расход домашних вещей и сам выбирает день проверки. Пользователь отвечает на вопросы, а не ведёт журнал каждого использования.

**Статус: запускаемый Telegram-бот с inline-callback, SQLite, независимыми опросами, быстрым добавлением и управлением предметами.** Проверки используют настоящий SQLite и поддельный Telegram API. Живое подключение, серверное развёртывание и домашний пилот не проводились.

## Правила

Каждый предмет имеет собственный прогноз и дату вопроса. Общие только час доставки и представление вопросов; нет общего дневного лимита или обучения на соседних предметах. Резерв — фиксированный допуск на ошибку, а не автоматически растущий запас. Настройка резерва не создаёт физические упаковки.

Неизвестно, отсутствие ответа, подтверждённое неиспользование и покупка — разные события. «Уже купили» уточняет текущий запас, не создавая выдуманную покупку в момент ответа. Рекомендация купить — не заказ.

## Быстрое добавление

Откройте `/add` или нажмите «Добавить предмет». Название можно выбрать готовой кнопкой, написать самостоятельно или прислать несколько названий по одному на строку.

```text
Название → [С резервом / Без резерва]
         → [Одна полная упаковка / Полная + одна запасная /
            Осталось примерно 50% / Сейчас нет / Указать остаток]
         → Проверка введённого → [Добавить]
```

Обычный путь после названия — три нажатия. На последнем экране доступны «Изменить остаток», «Уточнить срок расхода», «Назад» и «Отмена». Срок расхода необязателен: явно показанный начальный ориентир — 30 дней на упаковку, не выученный факт.

Готовые названия — только сокращение набора текста. Они не задают категорийные скорости расхода и не связывают модели предметов.

Можно отправить список:

```text
/add Зубная паста
Туалетная бумага
Мусорные пакеты
```

До 20 уникальных названий за раз, каждое до 80 символов. Бот последовательно предлагает настройки и подтверждение каждого предмета. Уже существующие названия и повторы без учёта регистра пропускаются. Новый предмет создаётся только после «Добавить».

`/add` продолжает незавершённое добавление, в том числе после перезапуска. «Отмена» внутри формы пропускает текущий предмет списка; `/cancel` отменяет всё оставшееся, сохраняя уже добавленные предметы.

## Callback и клавиатуры

После завершённого ответа или отмены остаётся сообщение-подтверждение **без inline-кнопок**. Между шагами старые кнопки заменяются кнопками следующего шага в том же сообщении. У заменённого вопроса в другом сообщении клавиатура удаляется отдельно, без изменения текста.

Проверяются владелец, исходное сообщение, версия экрана, разрешённое действие и ревизия предмета. Повторный ответ не применяется дважды. Нажатие старой кнопки не должно стирать уже показанную новую клавиатуру. Очистка и обновление сообщений проходят через сохраняемую очередь с повтором сетевых ошибок. `answerCallbackQuery` отправляется отдельно и не заменяет удаление клавиатуры.

[Подробный контракт и границы гарантии](docs/callback-onboarding.md).

## Команды и управление

| Команда | Назначение |
|---|---|
| `/items` | Реестр и проверка остатка |
| `/today` | Вопросы с наступившей датой |
| `/shopping` | Рекомендации пополнить активные предметы |
| `/add` | Добавление или продолжение незаконченной формы |
| `/cancel` | Отмена оставшегося добавления |
| `/manage` | Настройки, пауза, возобновление, архивирование |
| `/archive` | Архив и восстановление на паузе |

Пауза не прекращает прогнозируемый расход и не сдвигает сохранённую дату. Архивирование требует подтверждения и сохраняет историю. Настройки резерва, времени на покупку и максимального интервала проверки меняются с подтверждением только для выбранного предмета. [Управление предметами](docs/item-management.md).

## Запуск и обновление

Нужны Go и C-компилятор для SQLite/CGO. CI использует Go 1.27.1; `go 1.23.0` в модуле — совместимость языка, не рекомендация для сетевой эксплуатации.

```sh
git clone https://github.com/EugenSleptsov/hoarder.git
cd hoarder
make check
mkdir -p bin
CGO_ENABLED=1 go build -o bin/hoarder ./cmd/hoarder

export HOARDER_CHAT_ID='YOUR_NUMERIC_PRIVATE_CHAT_ID'
export TELEGRAM_BOT_TOKEN_FILE='/absolute/private/path/telegram-token'
export HOARDER_TIMEZONE='Europe/Berlin'
export HOARDER_POLL_TIME='21:00'
export HOARDER_DB='data/hoarder.db'
./bin/hoarder
```

Подставьте положительный ID личного чата и существующий файл токена вне Git. После запуска отправьте `/start`. Один владелец и один процесс на базу/токен; пустой день не вызывает уведомления.

**Перед обновлением сделайте согласованную резервную копию прежним бинарником.** Схемы v1/v2 автоматически переходят в v3. История предметов не переписывается; старые диалоги читаются. Старые бинарники не должны открывать v3. Не понижайте `PRAGMA user_version` вручную. [Запуск, backup и обновление](docs/running.md).

## Проверки и ограничения

`make check`: форматирование, `go vet`, тесты с race detector. `go run ./cmd/hoarder-sim`: офлайн-сценарий ядра. [Зафиксированные результаты](docs/verification.md).

Прогноз `interval-baseline-v1` не обучает сезонность и не рассчитывает откалиброванные вероятности. Наличие при произвольном скачке расхода не гарантируется. Подробная форма поддерживает до трёх закрытых и одну открытую стандартную упаковку. Начальные настройки: резерв 0/1, время на покупку 3 дня, максимальный интервал проверки 90 дней.

Переименование, смена единицы упаковки, исправление прошлых ответов, смена общего часа на существующей базе, несколько пользователей, health endpoint и автоматическая очистка/ротация ещё не реализованы. Исчезновение клавиатуры зависит от доступности Telegram; постоянные ошибки сохраняются для диагностики. Первое сообщение может продублироваться при падении до записи `message_id`; exactly-once внешняя доставка не заявляется.

Токены, рабочую базу и личный реестр не добавляйте в Git. Автоматических заказов/платежей, медицинских гарантий и учёта сроков годности нет.
