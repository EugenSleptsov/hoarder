# hoarder

bot keeping items

Бот на Go, который прогнозирует расход домашних вещей и сам выбирает день, когда уточнить остаток или напомнить о пополнении. Пользователь отвечает на вопросы, а не ведёт журнал каждого использования.

**Статус: запускаемый Telegram-бот с inline-кнопками, SQLite, независимыми опросами и управлением предметами.** Работают добавление, проверка остатка, рекомендации купить, пауза/возобновление, настройки и обратимый архив. Интеграционные тесты используют настоящий SQLite и поддельный Telegram API. Живое подключение, серверное развёртывание и домашний пилот не проводились.

## Основные правила

- **Предметы независимы.** Ответ о пасте не меняет прогноз бумаги. Общие только час доставки и представление вопросов; нет общего лимита предметов на день.
- **Резерв — фиксированный допуск на ошибку.** Размер резерва не увеличивается автоматически. Изменить свойство можно только явно, через подтверждение настройки; физический запас от этого не прибавляется.
- **Прогноз — основной механизм.** Не нужно самостоятельно сообщать об открытии резерва или каждом использовании.
- **Неизвестно — не значит не использовали.** Пропущенный ответ не останавливает расход. Рекомендация купить не считается покупкой. «Уже купили» уточняет текущий остаток, не создавая выдуманную покупку в момент ответа.

## Кнопочный интерфейс

`/start` → «Добавить предмет» → название текстом → резерв → примерная длительность упаковки → число закрытых упаковок → остаток открытой: **Полная / 75% / 50% / 25% / Пусто**.

Повторная проверка также предлагает «Не знаю / не смотрел» и «Не использовали» с подтверждением интервала за весь дом. Иногда уточняется отсутствие пополнений для корректного обучения. На предмет может требоваться несколько нажатий; минимизация этой нагрузки ещё требует проверки на практике.

Кнопки вызывают настоящий `callback_query`. Проверяются владелец, исходное сообщение, разрешённое действие, версия экрана и ревизия предмета. Двойной ответ не применяется повторно. Каждый переход сохраняется; диалог можно продолжить после перезапуска. `answerCallbackQuery` отправляется и при отклонении устаревшего ответа.

| Команда | Назначение |
|---|---|
| `/items` | Реестр и обычные проверки остатка |
| `/today` | Вопросы с наступившей датой |
| `/shopping` | Рекомендации пополнить активные предметы |
| `/add` | Добавление предмета |
| `/manage` | Управление существующими предметами |
| `/archive` | Архив и восстановление |

## Управление предметом

Откройте «Управление предметами» или `/manage`, затем выберите предмет:

```text
[Проверить остаток]
[Настройки]
[Приостановить опросы]
[Убрать в архив]
```

На паузе расход продолжает прогнозироваться. Сохранённая дата не сдвигается; после возобновления просроченный вопрос остаётся просроченным и участвует в следующем допустимом ежедневном опросе. Ручная проверка остатка доступна и не включает опросы автоматически.

Настройки: резерв **0/1 упаковка**, время на покупку **1/3/7/14 дней**, максимальный интервал проверки **7/30/90/180 дней**. Перед изменением бот показывает «было / будет» и просит подтверждение. Обновляются только план и рекомендация этого предмета, не физический запас. Сохранение прежнего значения не создаёт новое событие и не сдвигает дату.

Архивирование требует подтверждения, убирает предмет из обычного реестра, вопросов и списка покупок, но сохраняет историю. Восстановление возвращает предмет **на паузе**. Это не безвозвратное удаление данных. [Подробный контракт управления](docs/item-management.md).

## Запуск

Нужны Go и C-компилятор для SQLite/CGO. CI использует Go 1.27.1; минимальная директива `go 1.23.0` не является рекомендацией для сетевой эксплуатации.

```sh
git clone https://github.com/EugenSleptsov/hoarder.git
cd hoarder
make check
mkdir -p bin
CGO_ENABLED=1 go build -o bin/hoarder ./cmd/hoarder

export HOARDER_CHAT_ID='YOUR_NUMERIC_PRIVATE_CHAT_ID'
export TELEGRAM_BOT_TOKEN_FILE='/absolute/private/path/telegram-token'
export HOARDER_TIMEZONE='Europe/Berlin'
export HOARDER_POLL_TIME='21:00'
export HOARDER_DB='data/hoarder.db'

./bin/hoarder
```

Подставьте положительный числовой ID своего личного чата и существующий файл токена вне Git. После запуска отправьте боту `/start`. Поддерживается один владелец и один процесс на базу/токен. Пустой день не вызывает уведомления. Команды доступны в любое время.

**Обновление существующей установки:** до первого открытия базы новой версией сделайте согласованную резервную копию старой версией бота. База автоматически мигрирует с v1 на v2; старый бинарник после этого должен отказаться её открывать. Не понижайте `PRAGMA user_version` вручную. [Запуск, обновление и восстановление](docs/running.md).

## Компоненты и проверки

`internal/item` хранит независимое состояние и применяет воспроизводимые события; `forecast` считает две границы — пополнение и исчерпание; `schedule` сопоставляет сроки с общим часом. `dialog` — машина кнопочных диалогов; `sqlstore` — SQLite, журнал, транзакции, replay и backup; `bot` связывает команды, callback, управление, ежедневные сессии и outbox; `telegram` — HTTP-адаптер.

`make check` проверяет форматирование, `go vet` и тесты с race detector. `go run ./cmd/hoarder-sim` запускает офлайн-сценарий без Telegram. Тесты используют временные базы и фиктивный токен. [Результаты и границы проверки](docs/verification.md).

## Ограничения

Прогноз `interval-baseline-v1` **не обучает сезонность** и не рассчитывает откалиброванные вероятности. Наличие при произвольном скачке расхода не гарантируется. Форма поддерживает до трёх закрытых и одну открытую стандартную упаковку. Начальные настройки: резерв 0/1, время на покупку 3 дня, максимальный интервал 90 дней.

Переименование, смена единицы/размера упаковки, исправление прошлых ответов, изменение общего часа на существующей базе, несколько пользователей, health endpoint, автоматическая ротация backup и очистка служебных записей ещё не реализованы. Архив не удаляет данные из базы, резервных копий или истории Telegram.

Первое внешнее сообщение может продублироваться при падении между принятием Telegram и сохранением `message_id`. Уже отправляемое сообщение нельзя атомарно отменить из SQLite; устаревшие кнопки всё равно проверяются перед изменением данных. Exactly-once доставка не заявляется.

Не добавляйте токены, рабочую базу и личный реестр в Git. Автоматических заказов/платежей, медицинских гарантий и учёта сроков годности нет.
